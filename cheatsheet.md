\# Git Cheatsheet для QA



1\. \*\*Потрібно перевірити, які файли змінилися перед роботою з ними →\*\* `git status` → Git покаже поточну гілку та файли зі змінами, які ще не закомічені.



2\. \*\*Хочу подивитися, що саме змінилося у файлах до додавання їх у commit →\*\* `git diff` → побачу відмінності між поточними файлами та останнім commit.



3\. \*\*Я вже виконав `git add`, але хочу перевірити, що саме потрапить у commit →\*\* `git diff --staged` → Git покаже зміни, які вже знаходяться у staging area.



4\. \*\*Потрібно зберегти підготовлені зміни в історії →\*\* `git commit -m "Add login test"` → створиться новий commit із вказаним повідомленням.



5\. \*\*Хочу отримати останні зміни з GitHub, але поки не хочу об'єднувати їх зі своєю гілкою →\*\* `git fetch origin` → Git завантажить інформацію про нові зміни та оновить remote-tracking branches, але мої файли автоматично не змінить.



6\. \*\*Потрібно одночасно отримати зміни з GitHub і застосувати їх до поточної гілки →\*\* `git pull` → Git виконає отримання змін і спробує інтегрувати їх у поточну гілку.



7\. \*\*Хочу спочатку переглянути зміни колег, а вже потім вирішити, чи об'єднувати їх →\*\* `git fetch origin` → зміни завантажаться локально без автоматичного merge, тому я зможу перевірити їх перед інтеграцією.



8\. \*\*Після оновлення гілки виник конфлікт під час merge, і я вирішив не продовжувати →\*\* `git merge --abort` → Git спробує повернути репозиторій до стану, який був до початку merge.



9\. \*\*Я випадково почав merge, хоча мав спочатку закінчити свою локальну роботу →\*\* `git merge --abort` → поточний процес merge буде скасовано, щоб можна було повернутися до попереднього стану.



10\. \*\*Потрібно переглянути останні commit-и проєкту →\*\* `git log --oneline` → Git покаже історію commit-ів у компактному вигляді.



11\. \*\*Хочу дізнатися, як змінювався конкретний файл протягом історії проєкту →\*\* `git log -- path/to/file` → Git покаже commit-и, у яких змінювався саме цей файл.



12\. \*\*Потрібно побачити не тільки commit-и конкретного файлу, а й самі зміни в ньому →\*\* `git log -p -- path/to/file` → Git покаже історію файлу разом із diff для відповідних commit-ів.



13\. \*\*Хочу зрозуміти, у якому commit з'явився конкретний рядок у тесті →\*\* `git blame tests/login.test.js` → Git покаже для рядків файлу commit та автора, пов'язаних із кожним рядком.



14\. \*\*Потрібно створити окрему гілку для автоматизованого тесту знайденого бага →\*\* `git switch -c bug/login-test` → нова гілка створиться, і Git одразу переключить мене на неї.



15\. \*\*Хочу побачити всі локальні гілки перед перевіркою Pull Request →\*\* `git branch` → Git покаже локальні гілки та позначить поточну гілку.



16\. \*\*Я працюю над багом і хочу тимчасово прибрати незакомічені зміни, щоб переключитися на іншу задачу →\*\* `git stash` → поточні незакомічені зміни будуть тимчасово збережені, а робоче дерево стане чистішим.



17\. \*\*Потрібно повернути раніше відкладені локальні зміни після перевірки іншої задачі →\*\* `git stash pop` → останні збережені через stash зміни будуть застосовані назад, а запис stash зазвичай буде видалений.



18\. \*\*Я випадково втратив орієнтир після переключень гілок і хочу знайти попередній стан HEAD →\*\* `git reflog` → Git покаже журнал переміщень посилань, зокрема попередні позиції HEAD.



19\. \*\*Потрібно відкотити локальну гілку до стану до невдалого merge, який уже був завершений →\*\* `git reset --hard ORIG\_HEAD` → гілка та робоче дерево повернуться до стану, який Git зберіг перед merge; незбережені зміни при цьому можуть бути втрачені.



20\. \*\*Я завершив зміни у своїй гілці та хочу передати їх команді на перевірку →\*\* `git push origin bug/login-test` → локальна гілка буде відправлена на віддалений репозиторій, після чого можна створити Pull Request.
